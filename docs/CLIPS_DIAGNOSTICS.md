# VK Клипы: чёрный экран отдельной вкладки

## Симптом

Клипы, открытые из основной ленты VK Видео, могут воспроизводиться, но
отдельная вкладка «Клипы» открывает чёрный экран. Это **не** доказывает,
что виноват рекламный патч: нужно отличить ошибку сервера/сети, сбой
загрузки ленты, проблему SDK и краш Android.

Исторические регрессии описаны в `CHANGELOG.md` (0.2.8, 0.2.12–0.2.14).
Участки для проверки в `Patches.kt`: `Filter clip feed ads`
и `Filter Clips SDK ads`. Обе версии могут проходить статические
проверки, но ломать экран во время выполнения.

## Шаг 1. Снять лог с устройства

1. Включить «Отладку по USB» на Android, подключить телефон и разрешить ADB.
2. Запустить в PowerShell из корня проекта:

   ```powershell
   .\scripts\capture-clips-log.ps1
   ```

3. Открыть VK Видео, нажать на отдельную кнопку «Клипы», дождаться
   чёрного экрана и нажать Enter в PowerShell.
4. Сохранить `app-version.txt` и `clips-filtered-review-before-sharing.txt`.
   Перед отправкой проверить, что в файле нет персональных данных.
   **Не публиковать `logcat-private.txt`** — он остаётся локально.

При отсутствии `adb` в PATH скрипт пробует
`C:\AndroidLab\Sdk\platform-tools\adb.exe`. Можно указать `-AdbPath`
и `-Serial` вручную.

Перед сборкой диагностических APK сравнить с официальным VK Видео той же
Android-версии, желательно в отдельном профиле/защищённой папке, не
удаляя текущую модифицированную установку. Проверить также сеть с VPN
и без VPN.

## Шаг 2. Исключить влияние патчей

`Actions → VK Video auto build → Run workflow` на `main`.
Указывать `clip_mode`:

| Режим | Что отключено | Публикует Release |
| --- | --- | --- |
| `full` | Ничего | Только если upstream не в карантине и пройдены все проверки |
| `without-sdk` | `Filter Clips SDK ads` | Нет |
| `without-feed` | `Filter clip feed ads` | Нет |
| `without-both` | Оба фильтра | Нет |

В диагностическом режиме флаг `force_rebuild` необязателен: сборка
запускается принудительно. Остальные патчи (видео, реклама, подпись)
остаются прежними. Готовый APK с проектной подписью доступен только в
**Artifacts** соответствующего запуска (не в `Releases`).

Все варианты проверяются на **одной и той же Android-версии**
и одном аккаунте/устройстве, иначе результаты нельзя сопоставлять.
Сначала проверить `without-sdk`, затем `without-feed`.
Если билд падает на fingerprint новой VK Видео, никакой рабочий
диагностический APK не считается полученным.

Важно: `ci/runtime-quarantine.json` содержит текущие новые/непроверенные
версии. До успешного теста реального устройства автоматическая
публикация этих версий заблокирована, хотя Actions может собрать
диагностический APK и приложить отчёт.

## Шаг 3. Разобрать результаты

- **Официальная версия тоже чёрная**: проверять сеть, авторизацию,
  конфигурацию аккаунта и серверный API Клипов.
- **Официальная работает; `without-sdk` исправляет ошибку**:
  локализовать `ClipSdkAdVideoMapperFingerprint` и возврат `null`.
- **Официальная работает; `without-feed` исправляет ошибку**:
  проверить мутацию `ShortVideoRecomFeedDto` и синтетические callbacks.
- **Обе тестовые сборки чёрные**: искать ошибки загрузки вкладки и
  другие патчи; не объявлять виновника без logcat.

Не снимать версию с карантина и не выпускать релиз по одной лишь зелёной
проверке CI: нужен запуск Home, отдельной вкладки Clips, клипов из
ленты, обычного видео, профиля и сворачивание/возобновление приложения.
